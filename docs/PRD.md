# MeetingMind 产品需求文档（PRD）

| 项目信息 | 内容 |
|---|---|
| 产品名称 | MeetingMind（会议纪要智能助手） |
| 项目代号（snake_case） | `meeting_mind` |
| 文档语言 | 简体中文 |
| 文档版本 | v1.0（简单 PRD 档） |
| 交付形态 | **Web 应用**（桌面浏览器优先，Chrome / Edge 110+） |
| 技术栈 | Vite + React 18 + TypeScript + MUI（组件与主题）+ Tailwind CSS（布局与原子样式） |
| 云端 | 腾讯云 CloudBase（数据库 / 存储 / 登录 / AI 大模型），**必须支持无云降级** |
| 作者 | 许清楚（产品经理） |

### 原始需求复述

> 开发一款面向工作会议场景的软件，能够：① 实时聆听并转录会议音频（低延迟、准确）；② 区分不同发言者；③ 按议题或时间线整理讨论要点；④ 提取关键决议与待办事项；⑤ 输出层次清晰、便于导出与查阅的笔记文档。

---

## 1. 产品目标

**一句话目标**

> 让一场会议在结束的那一刻，就拥有一份「分得清谁说了什么、讲得清讨论了什么、拿得走决议与待办」的结构化纪要。

**三条价值主张**

| # | 价值主张 | 说明 | 可度量结果 |
|---|---|---|---|
| V1 | **零延迟感的实时记录** | 边说边出字，说话人归属随讲随标，会后不需要再"回忆" | interim 首字上屏 P95 ≤ 1.5s，会议结束时 100% 转写文本已就绪 |
| V2 | **从流水账到结构化** | 自动按议题切段 + 抽取决议/待办，把 1 小时录音压缩成 10 分钟可读的纪要 | 会后到拿到初稿 ≤ 15s，人工整理耗时下降 ≥ 60% |
| V3 | **人工校正是一等公民** | 承认浏览器端 ASR 与说话人识别的不完美，把"改对"做成最快、最低成本的交互 | 任意一条发言的归属/文本修改 ≤ 2 次点击，支持批量与撤销 |

## 2. 目标用户与核心使用场景

### 2.1 Persona

| Persona | 画像 | 核心痛点 | 关键诉求 |
|---|---|---|---|
| **P1 项目组长 · 李工** | 带 5–8 人小组，每周 4–6 场内部会议（站会、评审、复盘） | 会议多、记不过来；会后补纪要占用晚上时间；待办经常遗漏跟进 | 开完会立刻拿到纪要 + 待办清单，能一键分发 |
| **P2 产品经理 · 小张** | 频繁跨部门对齐，会议参与者不固定 | 讨论发散，事后难以还原"谁承诺了什么"；决议口径不一致 | 决议与待办要和原话可追溯，能定位到具体时间/发言人 |
| **P3 会议记录人 · 实习生小陈** | 被指派做会议记录，打字跟不上 | 手写漏内容，专业术语听不懂，格式不统一 | 实时字幕 + 术语可改 + 一键导出统一格式文档 |

### 2.2 核心场景

| 场景 | 描述 | 成功标准 |
|---|---|---|
| S1 部门周会（45–60min，6 人，圆桌） | 全程开启实时记录，多议题轮换，会后抽取待办并指派负责人 | 完整转写 + ≥3 个议题分段 + ≥3 条待办，人工校正 < 5 分钟 |
| S2 需求评审会（90min，8 人，远程 + 现场混合） | 讨论发散、打断多，重点是"结论"与"行动项" | 决议抽取召回 ≥ 60%，每条决议可回溯到原话 |
| S3 一对一沟通（20min，2 人） | 快速记录，聚焦共识与下一步 | 会议结束后 15s 内导出 Markdown 纪要 |

## 4. 需求池

> P0 = Must have（缺失则产品不成立）｜P1 = Should have｜P2 = Nice to have

### 4.1 P0（必须）

| ID | 需求名 | 描述 | 验收标准 |
|---|---|---|---|
| P0-01 | 会议生命周期控制 | 新建会议（标题、可选议程），开始 / 暂停 / 继续 / 结束；页面顶部常驻状态条显示录制时长与状态 | ① 四个状态互斥且可循环切换，状态持久化到本地 ② 时长计时误差 < 1s/10min ③ 结束时必须二次确认 |
| P0-02 | 麦克风设备选择与权限引导 | 调用 `getUserMedia` 获取麦克风；提供设备下拉选择；权限被拒时弹出图文引导（浏览器地址栏 → 站点设置） | ① 支持在多个输入设备间切换且切换后不中断已录内容 ② 权限被拒时引导 1 次点击可打开设置说明 ③ 非安全上下文（http 非 localhost）时明确提示需 HTTPS |
| P0-03 | 实时语音转写字幕流 | 使用浏览器 `SpeechRecognition(webkitSpeechRecognition)` 流式识别；`continuous=true`、`interimResults=true`；interim 文本灰色斜体实时刷新，final 结果落定为正式发言记录 | ① interim 首字上屏 P95 ≤ 1.5s ② interim→final 转换不丢字、不重复 ③ 断流（`onend`）时 3s 内自动重启且历史文本不丢 ④ 识别语种默认 `zh-CN`，可切换 `en-US` |
| P0-04 | 发言记录（Utterance）沉淀 | 每条 final 结果落为一条发言记录，含：序号、发言人、文本、起始/结束时间（相对会议开始）、来源（asr/manual） | ① 时间误差 < 2s ② 支持删除单条 ③ 全部发言在内存中按序可索引，1 小时会议（约 600 条）滚动无卡顿（>50fps） |
| P0-05 | 参会人管理 | 会前/会中增改参会人（姓名、角色、颜色）；上限 12 人；未设置时允许匿名发言 | ① 增改即时生效且不打断识别 ② 每位参会人有稳定色值用于时间轴与字幕着色 ③ 删除参会人时其发言归属改为「未知」而非丢失 |
| P0-06 | 当前发言人切换 | 顶部参会人头像条，单击切换"当前发言人"；快捷键 `Ctrl/Cmd + 1..9` 快速切换；未指定时归属「未知发言人」 | ① 切换后新产生的发言全部带该发言人 ② 当前发言人有高亮描边 ③ 切换响应 < 100ms |
| P0-07 | 发言人归属校正（一等公民） | 每条发言可单独改归属（下拉）；支持「从此处起批量改为 X」；支持按发言人批量重归属；支持撤销（Ctrl/Cmd+Z） | ① 单条修改 ≤ 2 次点击 ② 批量操作支持预览影响条数 ③ 撤销栈深度 ≥ 20 步 ④ 校正后的文本与归属在导出中原样保留 |
| P0-08 | 发言文本编辑 | 双击发言文本就地编辑；支持合并相邻同一人发言、拆分选中发言 | ① 编辑后 `source` 标记为 `edited` ② 合并/拆分保留时间顺序 ③ 编辑不触发页面重排闪烁 |
| P0-09 | 音频录制与留存 | 会议期间用 `MediaRecorder` 录制音频（webm/opus），与 `SpeechRecognition` **共享同一个 MediaStream** | ① 录制与识别可同时工作，互不抢占 ② 1 小时音频本地内存/磁盘占用 ≤ 150MB（opus） ③ 结束时产出本地可下载 Blob |
| P0-10 | 会议音频回放与时间轴 | 结束/暂停后可播放录音；点击任意发言跳转到对应时间点播放 | ① 跳转定位误差 ≤ 2s ② 播放中不阻塞其他编辑操作 |
| P0-11 | 议题分段（手动 + 自动辅助） | 手动：点击「+ 新议题」在当前位置插入分隔并命名；自动：AI 或本地规则（时间间隔 ≥ 90s + 话题切换关键词：接下来/我们看一下/下一个/关于…）预分段并提示用户确认 | ① 手动插入 ≤ 1 次点击 ② 自动分段建议可逐条接受/拒绝 ③ 纪要按议题分组呈现，段内按时间排序 ④ 支持议题改名与拖动排序 |
| P0-12 | 决议抽取 | 会后由 CloudBase AI 大模型（有云）或本地规则引擎（无云）从发言文本抽取决议候选，用户勾选/编辑/新增 | ① 每条决议可溯源到原始发言（点击跳转） ② 抽取结果 ≤ 15s 返回 ③ 支持标记"已确认" ④ 用户可手动新增/删除 |
| P0-13 | 待办事项抽取 | 同上抽取待办候选，含内容、可指派负责人、可选截止日期、优先级 | ① 待办可勾选完成 ② 负责人可从参会人列表选择 ③ 支持导出为独立清单 ④ 抽取 ≤ 15s 返回 |
| P0-14 | 纪要编辑页 | 结构化编辑：会议元信息（标题/时间/参会人）+ 议题分段（段名/要点）+ 决议列表 + 待办列表；全部可增删改序 | ① 编辑即保存（防抖 800ms） ② 支持拖动排序 ③ 编辑页与实时页字段一致 |
| P0-15 | 导出（四格式） | 导出 **Markdown(.md) / 纯文本(.txt) / JSON(.json) / 打印友好 HTML(.html)** | ① 四种格式内容一致、结构层次清晰（标题→议题→要点→决议→待办） ② 导出文件名含会议标题与日期 ③ 打印 HTML 含 `@media print` 样式，`Ctrl+P` 可直接出 PDF |
| P0-16 | 历史会议列表与检索 | 列表展示标题、日期、时长、参会人、发言条数；支持关键词搜索标题与正文、按日期倒序 | ① 100 条会议列表首屏渲染 < 1s ② 搜索输入防抖 300ms，结果 < 500ms ③ 支持删除会议（二次确认） |
| P0-17 | 本地持久化与崩溃恢复 | 无云环境下用 **IndexedDB** 存会议正文（大文本）+ localStorage 存偏好；每 5s 自动落盘 + 关键操作立即落盘 | ① 刷新/崩溃后重开页面自动恢复未结束会议 ② 1 小时会议数据写入耗时 < 300ms 不阻塞 UI ③ 存储失败时提示用户导出备份 |
| P0-18 | **Web Speech API 三级降级** | 见 §5.1 降级矩阵。必须保证：识别不可用时应用不白屏、不静默失效 | ① 不支持时页面顶部常驻黄色提示条说明当前模式 ② 任何一级降级下，议题分段/决议待办/编辑/导出/历史全部可用 |
| P0-19 | **无 CloudBase 降级** | 未配置 `env`/`accessKey` 或网络不可达时，自动进入「本地模式」，AI 整理由本地规则引擎接管 | ① 首次启动 3s 内判定模式 ② 本地模式下所有 P0 功能 100% 可用 ③ 全局设置页可手动切换/重试云端连接 |

## 5. 关键设计约束与降级方案（架构设计前提）

### 5.1 实时 ASR 三级降级矩阵

| 级别 | 触发条件 | 行为 | 用户可见提示 |
|---|---|---|---|
| **L0 理想路径** | `window.SpeechRecognition` 存在 + HTTPS/localhost + 麦克风授权 + 识别服务可达 | `continuous=true, interimResults=true` 流式识别；`onend` 自动重启；`onresult` 区分 interim/final | 绿色徽标「实时识别中」 |
| **L1 识别不可用** | 浏览器不支持（Safari/Firefox）/ 非安全上下文 / `network` 或 `service-not-allowed` 错误 | **自动切换为「仅录音 + 会后转写」**：MediaRecorder 继续录，界面改为录音模式；会后（有云）走 P1-04 云函数 ASR 兜底 | 黄色提示条：「当前浏览器不支持实时识别，已切换为录音模式，会后转为文字」 |
| **L2 完全无音频** | 麦克风权限被拒 / 无输入设备 / L1 且无云 | **切换为「手动记录模式」**：提供大文本框边会边记 + 会后支持粘贴外部转录文本；分段/抽取/导出全部照常 | 橙色提示条 + 权限引导按钮 |

> **重要风险提示（架构师必读）**：Chrome/Edge 的 `SpeechRecognition` 依赖厂商在线识别服务，在部分网络环境下会返回 `network` 错误或长时间无结果。因此：
> 1. 必须在启动时做 **8 秒探活**（`start()` 后 8s 无任何 `onresult` 且出现 `onerror` 即判定 L1）；
> 2. L1 路径的云函数 ASR 兜底（P1-04）是本项目在受限网络下真正可用的关键，**建议架构阶段就预留接口**；
> 3. **任何情况下不许静默失败**——模式降级必须在 UI 上明示。

### 5.2 说话人区分方案（务实取舍）

真实声纹分离在浏览器端不可靠且成本高。本产品采用 **「人工可控为主 + 启发式提示为辅」** 的方案：

| 手段 | 类型 | 说明 | 是否自动改写归属 |
|---|---|---|---|
| 参会人预设 | 会前 | 录入姓名/角色/配色，作为归属候选集 | — |
| 手动切换当前发言人 | 会中，主手段 | 点击头像 / `Ctrl+1..9` | ✅ 是（用户主动，可靠） |
| 静音段落自动切分 | 系统 | `SpeechRecognition` 结果边界 + 静音 ≥ 1.2s 自动切分 Utterance，归属沿用当前发言人 | ✅ 沿用当前发言人 |
| 能量启发式提示（P1-05） | 系统辅助 | 短时能量突变时提示「可能换人了」 | ❌ 否，仅提示一键确认 |
| 事后批量校正（P0-07） | 会后，一等公民 | 单条改、从此处起批量改、按人批量改、撤销 | ✅ 是（用户主动） |

**用户预期管理（必须写进产品文案）**：
- 产品不做"自动认出谁在说话"的承诺，承诺的是「**说清楚是谁说的，且改起来很快**」。
- 首次使用引导（Onboarding）中必须包含一次 15 秒的「切换发言人」演示。
- 无发言人预设或不切换时，发言归属为「未知发言人」，导出时以「未知发言人」呈现，不做猜测性标注。

### 5.3 CloudBase 使用与降级路径

| 能力 | 云端实现（有 CloudBase） | 本地降级（无 CloudBase） |
|---|---|---|
| 初始化判定 | `cloudbase.init({ env, accessKey, region })`；失败或 3s 超时 → 本地模式 | — |
| 登录 | `app.auth().signInAnonymously()`；升级用 `signInWithOtp({phone})` + `verifyOtp({token})` / `signInWithPassword` | 无登录，本地单用户 |
| AI 结构化整理 | `app.ai().createModel("hunyuan-exp")` → `model.generateText({ model: "hunyuan-2.0-instruct-20251111", messages })`；长输出用 `streamText` 逐字渲染 | **本地规则引擎**：关键词+句式模式匹配（"决定/确认/就按…来/一致同意" → 决议；"我来/你负责/@某人 + 下周/明天前/截止" → 待办）+ 时间间隔分段 |
| 数据持久化 | 文档数据库 `app.database()`，集合前缀 `mm_` | IndexedDB（正文大对象）+ localStorage（偏好/索引） |
| 音频留存 | CloudBase 存储 | 本地下载 / IndexedDB Blob |

**降级一致性要求**：两条路径产出的**数据结构完全相同**（同一套 TypeScript 模型），仅 `source` 字段标注 `ai` / `rule`，保证 UI、导出、检索逻辑零分叉。

### 5.4 数据模型（供架构师直接采用）

集合统一前缀 `mm_`，权限规则建议：**仅创建者可读写**（`doc._openid == auth.openid`）。

| 集合 | 关键字段 |
|---|---|
| `mm_meetings` | `_id, title, ownerId, startedAt, endedAt, durationMs, status(active/paused/ended), participants[], audioUrl?, audioLocalKey?, mode(web-speech/record-only/manual), schemaVersion, createdAt, updatedAt` |
| `mm_utterances` | `_id, meetingId, seq, speakerId?, text, startMs, endMs, source(asr/manual/edited), confidence?, isFinal, starred, createdAt` |
| `mm_topics` | `_id, meetingId, order, title, summary?, startUtteranceId, endUtteranceId, origin(ai/manual), createdAt` |
| `mm_decisions` | `_id, meetingId, content, sourceUtteranceIds[], order, confirmed, origin(ai/manual), createdAt` |
| `mm_action_items` | `_id, meetingId, content, assigneeId?, dueDate?, priority(P0/P1/P2), status(todo/done), sourceUtteranceIds[], origin, createdAt` |
| `mm_participants` | `_id, meetingId, name, role?, colorIndex, order, createdAt` |

> 每个集合必须有对应 TypeScript 类型定义作为单一事实来源；所有数据库操作需校验返回 `code` 并以可读中文提示错误。

### 5.5 技术栈说明

默认采用 **Vite + React 18 + TypeScript + MUI + Tailwind CSS**（符合团队默认栈）。理由与分工：
- MUI 负责**组件与主题**（Dialog、Menu、Select、Snackbar、主题色）；
- Tailwind 负责**布局与原子样式**（Grid、间距、响应式），两者通过 MUI 的 `sx` + Tailwind 类名并存，**建议关闭 Tailwind preflight 避免与 MUI 样式冲突**（交架构师决策）。

## 7. 关键指标定义

### 7.1 转录性能指标

| 指标 | 定义 | 目标 |
|---|---|---|
| **首字上屏延迟** | 从用户开始发声到界面出现第一个 interim 字符的时间 | P50 ≤ 800ms，**P95 ≤ 1.5s** |
| **最终确认延迟** | 从说完一句到该句由 interim 变为 final 的时间 | P95 ≤ 2.5s |
| **断流恢复时间** | `onend` 触发到自动重启并继续接收结果的时间 | ≤ 3s，且文本零丢失 |
| **长时稳定性** | 60 分钟连续会议的非计划中断次数 | ≤ 2 次，且每次自动恢复 |
| **音频录制完整性** | 录制时长 / 会议时长 | ≥ 99% |

### 7.2 准确率口径

| 指标 | 计算口径 | 目标 |
|---|---|---|
| **字错误率 CER** | `(替换数S + 删除数D + 插入数I) / 参考文本总字符数N`；中文按字符计，**计算前统一去除标点与空格** | 安静环境单人近场：CER ≤ 8%；普通会议室 3–6 人：CER ≤ 15% |
| **关键词准确率** | 产品名词/人名/专有名词的命中率（单独统计，因通用 ASR 最弱） | ≥ 70%（配合术语词库可提升） |
| **发言人归属免校正率** | `1 − (被用户修改过归属的发言条数 / 总发言条数)`；仅在用户主动切换发言人的前提下统计 | ≥ 70% |
| **决议抽取召回 Recall** | `正确抽取条数 / 人工标注决议总数` | ≥ 0.60 |
| **决议抽取精确 Precision** | `正确抽取条数 / 系统抽取总条数` | ≥ 0.70 |
| **待办抽取 Recall / Precision** | 同上，口径一致 | ≥ 0.60 / ≥ 0.70 |
| **校正后最终准确率** | 用户 5 分钟人工校正后，纪要中决议与待办的正确率 | = 100%（产品承诺的下限） |

> **口径说明**：CER 需以「人工听录的参考文本」为基准，在 3 场真实会议（总时长 ≥ 2 小时）上抽样测定，每场随机抽取 5 个 2 分钟片段。

### 7.3 整理与导出指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 纪要生成时延 | 点击「结束会议」到结构化纪要初稿渲染完成 | ≤ 15s（1 小时会议，云端）；≤ 3s（本地规则引擎） |
| 导出成功率 | 四种格式各导出 1 次均成功且内容完整 | 100% |
| 导出格式清单 | **Markdown(.md)、纯文本(.txt)、JSON(.json)、打印友好 HTML(.html)**；P1 追加 DOCX(.docx)、PDF(打印) | — |
| 首屏加载 | 应用到可交互（TTI） | ≤ 2s（本地 4G 网络） |
| 崩溃恢复率 | 模拟刷新后未结束会议数据的恢复比例 | 100%（文本），音频 ≥ 最近 5s |

## 8. 待确认问题与已作假设

### 8.1 假设（按此推进，不需等待确认）

| # | 项 | 已采用假设 | 理由 |
|---|---|---|---|
| A1 | 部署与网络 | 开发环境 `localhost`（SpeechRecognition 要求的必要条件）；生产部署到 **HTTPS** 静态托管（CloudBase 静态网站托管） | 非安全上下文 `getUserMedia`/`SpeechRecognition` 不可用 |
| A2 | 识别语种 | 默认 `zh-CN`，设置项可切 `en-US`；不做自动语种检测 | 会议场景语种稳定，做检测增加复杂度与延迟 |
| A3 | 会议规模上限 | 单场会议参会人 ≤ 12 人，发言记录 ≤ 2000 条（约 3 小时） | 覆盖 95% 内部会议；超出时提示分段新建会议 |
| A4 | 音频保留策略 | 本地模式下音频默认**不长期保存**，会议结束提供一次性下载；云端模式下按 P1-03 上传 | 避免 IndexedDB 配额（通常几百 MB）被音频占满 |
| A5 | 存储配额 | IndexedDB 仅存文本与元信息；接近配额（>80%）时提示用户归档导出 | 文本 1 小时会议约 300KB，安全 |
| A6 | AI 模型 | CloudBase AI 使用 `hunyuan-exp` provider 下的 `hunyuan-2.0-instruct-20251111`；长输出用 `streamText` 流式渲染 | 依 CloudBase Web AI 官方推荐；具体可用型号由架构师在控制台核对 |
| A7 | AI 调用时机 | 仅在「结束会议」时调用一次全量整理（议题分段 + 决议 + 待办合并为 1–2 次请求）；会中不调用 | 控制成本与会中性能抖动；长文本按 8000 字分片 |
| A8 | 登录 | 默认匿名登录，不强登；未登录功能不受限 | 降低使用门槛，符合"开箱可跑"约束 |
| A9 | 术语词库 | P0 不做自定义词库，P2-07 再考虑 | P0 聚焦主链路 |

### 8.2 待确认问题（不阻塞开发，需用户/后续确认）

| # | 问题 | 影响 | 建议答复方向 |
|---|---|---|---|
| Q1 | 目标运行环境是否能稳定访问 Chrome 的在线识别服务？若否，**是否需要把 P1-04（云函数 + 腾讯云 ASR 兜底）提前到 P0？** | 决定 L1 路径是否有出路，是本项目最大的可用性风险 | 建议：先做 P0 手动记录兜底；若实测网络不通，立刻将云函数 ASR 提升为 P0 |
| Q2 | 腾讯云 ASR 的密钥与开通状态（录音文件识别 vs 实时语音识别）？ | 决定兜底路径的延迟（分钟级 vs 秒级） | 需用户提供已开通的 ASR 服务与密钥；否则仅用录音+会后人工/粘贴文本 |
| Q3 | 是否需要**系统内音频**（如腾讯会议/飞书的共享声音）采集，而不只是麦克风？ | 远程会议场景下麦克风录不到对方声音，是常见刚需 | 浏览器无法直接采集系统音频；需用户选择"扬声器外放 + 麦克风收音"或安装虚拟声卡（需在引导中说明） |
| Q4 | 会议内容敏感度：是否允许音频/文本上传到 CloudBase？ | 影响是否需要提供"纯本地、永不上传"开关 | 建议：设置项提供「数据上云」总开关，默认开，敏感会议可一键关闭 |
| Q5 | 是否需要多人协作编辑同一份纪要（P2-01）？ | 影响数据模型是否需要权限/冲突合并字段 | 建议 P2 再做，P0 保持单用户模型 |
| Q6 | 移动端/平板是否需要支持？ | 移动端 Safari 无 `SpeechRecognition`，需走 L1 | 建议 P0 只做桌面 Chrome/Edge；移动端仅提供"查看/导出纪要"的只读适配 |

## 9. 验收与发布范围（MVP 定义）

**MVP = 全部 P0（P0-01 ~ P0-19）**，判定可发布的额外门槛：

1. 在 Chrome 最新版完成 1 场真实 60 分钟会议的完整走查，全程无人工干预重启；
2. 在**无 CloudBase 配置**的全新环境，`npm run dev` 打开即可完成：录音→字幕→分段→抽取→导出四格式→历史检索（P0-17/P0-19 通过）；
3. 在**模拟不支持 SpeechRecognition** 的浏览器（移除 API）下，自动进入 L1/L2 且除实时字幕外全部功能可用；
4. 关键指标（§7）在 3 场真实会议上完成测量并达标。
